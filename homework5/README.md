# Домашнее задание 5: Генерация тестов

## Цель
Реализовать компонент генерации тестов из результатов символьного анализа.

## Задания

### Задание 5.1: Реализация генератора тестов

В файле `test_generator.go` необходимо реализовать функцию, генерирующую тестовый файл для переданного файла.
В результате, функция должна возвращать путь до тестового файла (он должен располагаться рядом с переданным и название должно заканчиваться на `_test.go`), содержащего
сгенерированные тест-кейсы для всех функций, доступных в переданном на анализ файле. Тест-кейсы необходимо генерировать из 
результатов работы `analyser.Analyse`.

### Задание 5.2: Проверка работы генератора

Проверьте работу генератора тестов на примерах из **homework3** (`homework3/examples/test_functions.go`). 
Для этого используйте `coverage_checker.go` - он вызывает генератор тестов и выводит собранное тестовое покрытие. 

### Задание 5.3*: Добавление генерации в CI/CD

При желании, настройте CI/CD в репозитории таким образом, чтобы в нем был этап автоматического запуска `coverage_checker.go`
на файлах с примерами тестового кода.

**Сгенерированный тестовый файл для hw3/examples**

## Реализация

- `internal.GenerateTestFile` собирает SSA всего пакета (все `.go` файлы каталога, кроме тестов), анализирует каждую
  функцию переданного файла и записывает рядом `<имя>_test.go` с тестом `Test_<функция>` на каждую функцию.
- Для каждого найденного пути строится модель условия пути: из неё берутся аргументы, а ожидаемые результаты — это
  символьные возвращаемые значения, вычисленные на модели. Для путей с паникой тест проверяет, что функция паникует
  с тем же сообщением. Генератор сначала ищет модель с небольшими целыми аргументами (±10, затем ±1000) и без NaN.
- Пути отбираются жадно по покрытию переходов между блоками SSA (не блоков: например, `break` — это переход без
  собственного блока), после чего лишние пути отбрасываются. Для генерации анализатор разворачивает символьные циклы
  до 200 итераций и тратит на одну функцию не больше 2 минут.
- Функции с пока не поддерживаемыми конструкциями (вызовы, структуры, указатели, массивы — ДЗ6) пропускаются,
  в сгенерированном файле остаётся комментарий с причиной.
- `coverage_checker.go` запускает только сгенерированные тесты, чтобы другие тесты каталога не влияли на покрытие.

Результат для `homework3/examples/test_functions.go` — `homework3/examples/test_functions_test.go`
(46 тест-кейсов, покрытие 100%):

```bash
go run ./homework5 homework3/examples/test_functions.go
```

CI (`.github/workflows/ci.yml`) собирает проект, запускает линтер, тесты и `coverage_checker` на примерах ДЗ3.
