# Домашнее задание 3: Внутрипроцедурный анализ основных конструкций

## Цель
Реализовать основной цикл анализатора, а также интерпретацию основных языковых конструкций.

## Задания

### Задание 3.1: Реализация основного цикла анализатора

В файле `analyser.go` необходимо реализовать функцию `Analyse(source string, functionName string) []Interpreter` таким образом,
чтобы она выполняла основной цикл работы анализатора — доставала из `Analyzer.StatesQueue` при помощи `Analyser.PathSelector` следующее состояние
интерпретатора для исполнения, вызывала шаг динамической интерпретации, и складывала все получившиеся состояния обратно в приоритетную очередь
до тех пор, пока не сработает глобальная стратегия остановки (стратегию остановки выберите и реализуйте самостоятельно).

### Задание 3.2*: Реализация Path Selectors

При желании, реализуйте дополнительные стратегии выбора пути в файле `path_selector.go`.

### Задание 3.3: Интерпретация основных языковых конструкций

В файле `dynamic_interpreter.go` реализуйте следующие методы:

* `interpretDynamically(element ssa.Instruction) []Interpreter`, который по заданной ssa инструкции проводит шаг интерпретации
и возвращает полученный набор новых состояний
* `resolveExpression(value ssa.Value) symbolic.SymbolicExpression`, который по заданному expression получает символьное выражение.

Интерпретация должна поддерживать все основные языковые конструкции - ветвления, примитивы, бинарные и унарные операции, циклы, ...
За исключением вызовов функций, операций с массивами, объектами и указателями. На данном этапе требуется внутрипроцедурный анализ.

## Что сдавать

**Реализация в общей кодовой базе:**
- `../internal/analyser.go`
- `../internal/dynamic_interpreter.go`
- `../internal/path_selector.go`



## Реализация

- `internal.Analyse` строит SSA функции, создаёт начальное состояние с символьными параметрами и в цикле
  достаёт из `StatesQueue` состояние с наибольшим приоритетом (`PathSelector`), исполняет одну инструкцию
  и кладёт полученные состояния обратно; завершённые пути (возврат или паника) попадают в `Results`.
- Стратегия остановки (`internal.Options`): анализ прекращается, когда очередь пуста или исчерпан глобальный
  бюджет инструкций `MaxSteps` (по умолчанию 10000). Путь отбрасывается, если символьно ветвится в одном
  блоке больше `MaxBranchVisits` раз (по умолчанию 20) — это ограничивает развёртку циклов с символьным
  условием, не затрагивая циклы с конкретными границами.
- Path selectors: BFS (по умолчанию), DFS, случайный и `CoverageGuidedPathSelector`, который предпочитает
  состояния в реже посещённых блоках.
- Поддерживаются ветвления, циклы и phi, целые типы всех разрядностей (битовые векторы с семантикой
  переполнения Go), `float32`/`float64` (IEEE 754), `bool`, бинарные, унарные, побитовые операции, сдвиги
  и преобразования типов. Деление на ноль и отрицательный сдвиг порождают отдельный путь с паникой,
  `panic(...)` завершает путь с сообщением. Выражения над константами сворачиваются, недостижимые ветви
  отсекаются решателем Z3.

Проверка: `go test ./internal/... ./homework3/...` — тест в `examples/` для каждого найденного пути
каждой функции из `examples/test_functions.go` строит модель условия пути, исполняет функцию конкретно
на этих входах и сравнивает результат с символьным.
